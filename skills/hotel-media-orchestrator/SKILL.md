# 酒店新媒体总编排

## 执行原则

1. 先识别任务模式：`daily`、`swap`、`focus-topic`、`regenerate`、`publish`、`review` 或 `performance`。
2. 先读取当前测试账号，禁止混用其他酒店的事实、图片、历史数据和账号设置。
3. 按任务选择专项技能；不得跳过事实约束与合规审核。
4. 把用户要求定义为创意简报中的“做什么”，把表达方式交给内容与视觉技能。
5. 每个结论保留证据字段，每个缺失事实写入 `evidenceGaps`，不得用常识补齐酒店事实。
6. 输出失败时区分：数据不足、模型格式错误、合规阻断、素材不足、外部适配器未授权。

## 技能路由

| 模式 | 必选技能 | 目标 |
|---|---|---|
| daily / swap | 事实约束、选题策略 | 只返回三个不同方向，不生成成稿 |
| focus-topic / regenerate | 事实约束、内容生产、视觉选材、合规审核 | 围绕指定方向重写 |
| publish | 事实约束、合规审核、发布补全 | 生成可提交的发布表单 |
| performance | 数据复盘、选题策略 | 形成下一轮优化策略 |

## 标准执行链

1. 建立当前阶段的 `executionContext`：账号、任务模式、品牌、平台，以及本阶段 RAG 已召回的数据。
2. 只运行 `skillPlan` 中列出的技能，不提前执行后续阶段，也不读取本阶段未挂载的数据。
3. 选题阶段只返回三个方向；内容阶段只围绕 `focusTopic` 返回一条成稿和五图计划。
4. 内容与发布阶段执行合规门禁；质量分低于 70、存在高风险或缺少必要图片时，不得标记为直接可发布。
5. 返回结构化结果和 `executionTrace`，说明启用技能、关键决策、证据缺口与人工确认项。

## 输出总契约

- 始终输出纯 JSON，不使用 Markdown 或代码围栏。
- 选题阶段的 `recommendations` 恰好 3 条，角度、钩子和素材方案不得重复，且不得输出 `content`。
- 内容阶段的 `content` 必须包含标题、正文、标签、事实引用、五图视觉计划、地点和自检结果，且不得输出 `recommendations`。
- 发布与复盘阶段分别只输出发布表单或复盘结果，不回退生成选题与成稿。
- `executionTrace.skills` 按真实执行顺序列出技能 ID。
- 不得声称已抓取实时热点、实时房价、实时房态或已真实发布，除非输入明确提供相应结果。

详细状态机、错误类型与数据契约见 [references/execution-contract.md](references/execution-contract.md)。

模型调用只加载当前阶段需要的精简指令，见 [references/runtime-prompt.md](references/runtime-prompt.md)；完整 SKILL.md 不再整体塞入每次提示词。
