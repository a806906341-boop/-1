# 酒店内容生产

## 写作流程

1. 读取选题简报、证据包、品牌语气、目标受众、平台、素材计划和历史内容。
2. 先确定唯一核心信息，再选择钩子，不同时堆叠多个卖点。
3. 标题控制在 20 个中文字符内；正文目标约 120 个中文字符，允许 100-140 字。
4. 正文形成“场景/问题 → 两至三个可核验信息 → 适用人群或选择建议 → 轻行动引导”，不写空泛形容词串。
5. 生成 3-5 个标签，组合地点、住宿品类、场景和内容主题，禁止无关蹭流量。
6. 同时输出封面短句、视觉叙事顺序、评论引导和发布字段建议。
7. 将所有事实性表达登记到 `claimEvidence`，由合规技能复核。
8. 从 `locationContext` 绑定当前酒店/门店名称、事实地址和经纬度；平台 POI ID 只能沿用授权适配器结果，未匹配时明确标记“待平台匹配”。

## 表达要求

- 使用自然口语，避免“尊享、邂逅、赋能、天花板、封神”等模板化 AI 词。
- 品牌语气优先于通用爆款风格。
- 开头必须在一秒内让用户知道地点、场景或问题之一。
- 不编造第一人称入住体验，不伪装住客评价。
- 不承诺效果，不制造虚假稀缺，不默认使用夸张表情和感叹号。
- 行动引导可以是收藏、评论、查看定位或进入官方预订入口，不能引导私下交易。
- 重新生成时必须说明变化维度：钩子、受众、场景或表达节奏。
- 重新生成必须读取 `previousContent`，至少改变钩子、信息组织顺序、CTA/评论引导、图片组合/封面中的两项；禁止复用上一版首句或只做同义改写。
- 正文不足 100 字或超过 140 字视为不合格，必须在当前内容阶段自动重写，不把残缺成稿交给前端截断。

## 输出内容

输出 `title`、`body`、`tags`、`coverText`、`hook`、`cta`、`commentPrompt`、`rewriteSummary`、`location`、`shotPlan`、`materialCategory`、`factReferences`、`claimEvidence`、`requiresConfirmation` 和 `selfReview`。

平台写作与内容模板见 [references/platform-playbook.md](references/platform-playbook.md)。
