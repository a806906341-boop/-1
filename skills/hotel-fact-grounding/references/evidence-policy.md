# 证据与事实政策

## 目录

## 1. 来源等级

- A：商家人工确认、合同或后台已验证数据。
- B：OTA 酒店官方字段、酒店上传素材及明确设施标签。
- C：OTA 用户点评和用户上传图片，仅可作为体验线索。
- D：模型推断、行业常识、图片猜测，不可直接用于对外事实。

## 2. 稳定性

- 稳定：名称、地址、建筑或长期设施。
- 半稳定：服务项目、营业时间、交通安排、周边配套。
- 易变：价格、房态、折扣、套餐、库存、活动、天气、热度。

半稳定信息需关注更新时间；易变信息每次发布前必须人工确认。

## 3. 可写与不可写

可写：输入中明确存在的房间、公区、餐饮、位置、服务和 POI 距离。不可写：未提供的海景、苍山景、接送、免费权益、宠物政策、早餐数量、房间面积和价格。

“附近”应由明确距离支持；“步行可达”必须有步行数据；仅有直线距离时写“直线距离约 X 米”。

## 4. 冲突处理

同一字段冲突时优先 A，其次 B。无法判断时不选边，写入 `conflicts` 并要求确认。禁止将多个来源拼接成一个更强的宣传结论。

## 5. 引用格式

`factReferences` 使用 `字段名｜来源`，例如：`地址｜OTA`、`特色设施｜酒店上传`。需要引用数值时，在 `claimEvidence` 中保留原值，便于发布前核对。
