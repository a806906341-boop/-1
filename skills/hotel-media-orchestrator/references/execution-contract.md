# 执行契约

## 目录

1. 输入状态
2. 执行状态机
3. 决策优先级
4. 错误与降级
5. 可观测性

## 1. 输入状态

一次执行至少需要：账号 ID、酒店名称、城市、酒店类型、任务模式、知识库事实、素材摘要和最近内容。缺少品牌语气时使用“真实、克制、有地点感”；缺少历史数据时允许冷启动，但必须标记 `coldStart=true`。

事实分为：稳定事实、易变事实、用户声明、模型推断。只有前三类可用于发布文案；模型推断只能用于策略，不可作为对外宣称。

## 2. 执行状态机

`received → grounded → planned → drafted → visualized → reviewed → ready`。

- 任何事实缺口进入 `needs-confirmation`。
- 任何高风险进入 `blocked`。
- 模型 JSON 无法解析进入 `format-error`，允许一次格式修复，不允许静默伪造输出。
- 发布适配器未授权进入 `adapter-pending`，仍可保存完整发布草稿。

## 3. 决策优先级

1. 法律与平台安全。
2. 酒店事实真实性。
3. 当前账号数据隔离。
4. 素材可执行性。
5. 品牌一致性。
6. 传播效率与创意。

高层规则与低层规则冲突时按此顺序处理。不得为了传播性牺牲真实性。

## 4. 错误与降级

- 模型不可用：使用确定性 532 选题和模板草稿，明确标记 `source=rule-fallback`。
- 素材分类不足：改用真实可用分类，或返回补拍清单；不得用无关图片凑数。
- 易变信息缺失：删除具体数字，改为“以门店/平台当日信息为准”，并要求确认。
- 历史数据不足：使用冷启动策略，优先品牌差异点、位置、房间和公共区域。
- 发布失败：保留完整表单、失败原因、重试状态和幂等标识。

## 5. 可观测性

每次模型执行记录：规则版本、模型名、任务模式、启用技能、生成时间、token 使用、质量分、风险等级、事实引用数量、人工确认项。不得记录 API Key。
