# 住得满 AI 内容助手

基于《住得满 AI 内容助手产品需求文档 PRD v1.4》、产品原型、抖音来客素材指南、酒店运营规则表和大理 100 家酒店调研数据实现的可运行工程版应用。选题推荐与内容生成可直接调用通义千问模型。

## 现役入口与真相源

- 内部开发版：`http://localhost:5173/`，包含规则中心、知识库、适配器状态和研发诊断信息。
- 正式用户版：`http://localhost:5173/user-a.html`，作为“住得满”中的“AI 内容助手”功能模块，只展示用户需要操作的业务界面。
- 当前实现以根目录 `src/`、`server.mjs`、`skills/` 和 `tests/` 为准；本 README、`ARCHITECTURE.md` 与 `AI_RULES.md` 是现役说明。
- `住得满AI内容助手_产品需求文档_PRD_v1.4.md` 是当前产品实施基线；v1.3 文件仅作为历史版本保留。
- 现役系统入口仅为 `/` 与 `/user-a.html`。历史用户入口会兼容跳转到正式用户版；其他单文件原型不进入本次 GitHub 双端更新包。
- 本包是 2026-07-27 双端交付基线，不包含内容运营中台及其入口文件。

正式用户版已从方案 A 原型转为系统入口：`user-a.html` 只负责页面壳和样式入口，`src/entry-user.js` 负责正式用户版挂载，业务状态、AI 调用、RAG、素材、发布、互动和数据均复用现役系统模块，不维护第二套静态假数据页面。

给设计师快速审阅时，可直接发送根目录的 `住得满AI内容助手_正式用户版_设计审阅原型.html`。该单文件由现役用户版源码生成，可双击查看桌面/移动响应式布局和主要跳转；它使用明确的本地规则演示，不连接接收方电脑上的模型或抖音账号。系统界面更新后执行 `npm run build:design-prototype` 重新生成，禁止手工维护分叉版本。

## 当前能力

- 首次初始化与商家知识库
- 正式用户首页直接呈现“今日主推选题”，把选题标题、推荐理由、适合人群、内容讲法和素材基础分栏展示；主动作统一为“立即生成这条图文”
- 按酒店类型及 532 原则推荐选题
- 生成标题、约 120 字正文、标签，以及固定“1 张封面 + 4 张内容图”的历史去重、叙事排序图片组合
- 按酒店与目标平台检查最近 10 篇用图、最近 8 篇封面、最近 30 篇文案和最近 5 篇选题指纹；自动换图、换角度、换题最多 3 轮，仍不足时阻止进入发布并给出不超过 6 项的具体补拍建议
- “换一版”必须更换封面、至少替换 2 张图片、重写标题与正文首句；未达到差异要求时保留原版
- 三个独立测试账号：古城一号院、丽舍海景民宿、泊心云舍 MCA；分别载入 293、242、389 张 OTA 实拍图和酒店资料
- 测试账号之间独立保存草稿、知识库、素材使用、排期、发布记录与通知
- 极限词、敏感词、易变信息、图片真实性基础校验
- “7 天自动运营”是每周主动选择的可选功能，默认不开启且不自动续期；可选择只生成选题、自动准备后确认或按计划发布，并随时暂停、跳过或结束
- “我的”中不再保留独立创作偏好模块；7 天设置页只保留运行方式、时间平台和提醒三项核心决策，内容偏好折叠，系统必做规则只读展示
- 开启流程固定为“保存设置或生成预览 → 检查 7 天计划 → 明确确认开启”，运行中主入口直接进入驾驶舱
- 7 天页面使用“整周概览 + 单日详情”：移动端一次只展开一天，并展示选题、正文、五图、平台适配、检查和发布队列等生产阶段
- 用户版按抖音、小红书、微信视频号分别生成标题、正文和标签版本；抖音保留创作者中心字段逻辑，未获得直发能力的平台生成发布包并等待客户端确认
- 平台账号页明确区分“官方接口提交”和“客户端接力”，不会把本地演示或发布包伪装成平台发布成功
- 发布状态、失败原因与重试
- “我的”可进入酒店图库、酒店资料和发布平台；保留原经营基础能力与 4 项新媒体增长服务
- 酒店图库支持一次上传最多 30 张自有图片、图片压缩、重复识别和场景初分；素材继续参与自动检索、去重与五图编排
- 曝光/互动看板及 200% 峰值提醒
- 桌面端与移动端预览
- 浏览器本地持久化、JSON 导入/导出
- 将 `大理100家酒店调研交付_20260716` 作为 OTA 在线抓取结果快照，可在 100 家酒店间切换并重建知识库/素材库

### OTA 图片与 GitHub 仓库

`src/ota-snapshot.js` 已保留 100 家酒店、18,808 张图片和 2,260 个 POI 的结构化抓取结果。三个测试账号（古城一号院、丽舍海景民宿、泊心云舍 MCA）的 924 张照片已打包在 `assets/hotels`，可直接用于素材检索、自动选图和内容生成；其余酒店使用快照中的 `originalUrl` 加载 OTA 原图。完整原始下载缓存约 2.3GB，因此不整体提交到普通 GitHub 仓库。
- 本地 Node.js 后端安全接入阿里云百炼 OpenAI 兼容接口
- 由 8 个项目级阶段 Skills 管理选题、事实、写作、视觉、合规、发布与复盘；当前选题/内容两个模型接口实际装载其中 6 个，发布/复盘两个 Skill 作为本地流程与未来生产适配器的治理契约
- 选题与内容生成使用两个独立模型接口：先返回 3 条选题，用户选定后才生成 1 条成稿
- 每阶段只读取对应 `references/runtime-prompt.md`，完整 `SKILL.md` 用于治理和审阅，不再全量塞入每次调用
- 本地 RAG 按当前酒店和题目召回 Top-K 事实、历史与图片候选，未命中的资料不进入模型上下文
- 模型图片 ID 必须来自本轮候选白名单；服务端再执行字段规范、事实引用、历史相似度、风险和 100 分质量门禁
- 内部开发版“AI 规则中心”可展开查看完整 Skill、短运行提示词、四阶段装载计划、RAG 策略和实际系统提示词；正式用户版不展示研发规则

## 运行

本项目无需安装依赖，需要 Node.js 18+。在项目根目录执行：

```bash
npm run serve
```

然后根据用途访问：

- 内部开发版：`http://localhost:5173/`
- 正式用户版：`http://localhost:5173/user-a.html`

### macOS 常驻服务

当前开发机已安装用户级 `LaunchAgent`：`com.zhudemax.ai-content-assistant`。登录后自动启动，进程异常退出时自动拉起，不依赖 Codex 任务或终端窗口持续打开。

- 配置源文件：`scripts/com.zhudemax.ai-content-assistant.plist`
- 安装位置：`~/Library/LaunchAgents/com.zhudemax.ai-content-assistant.plist`
- 查看状态：`npm run service:status`
- 正常日志：`/tmp/zhudemax-ai-content-assistant.log`
- 错误日志：`/tmp/zhudemax-ai-content-assistant.error.log`

如果以后移动项目目录或更换 Node.js 安装路径，需要同步修改并重新加载该 plist。

也可以使用任意静态文件服务器。由于应用采用 ES Modules，不建议直接双击 `index.html` 以 `file://` 打开。

## 连接通义千问

方式一：启动应用后进入“系统设置”，填写接口地址、模型名称和 API Key。Key 只保存在本地后端进程内存中，服务重启后清除。

方式二：复制 `.env.example` 为 `.env.local`，只在本机填写：

```bash
DASHSCOPE_API_KEY=你的Key
AI_BASE_URL=https://你的业务空间域名/compatible-mode/v1
AI_MODEL=qwen3.7-max-2026-06-08
```

`.env.local` 已被 `.gitignore` 排除，不得提交或分享。

## 数据与安全

- 默认数据保存在当前浏览器的 `localStorage` 中。
- 选题推荐和内容生成可调用真实通义千问；内容阶段会从当前账号 RAG 召回的图片候选中选图。“发布”使用本地演示适配器，不会操作真实抖音账号。
- OTA 适配器默认处于“抓取成功”状态，读取本地交付快照中的 100 家酒店、18,808 张图片索引和 2,260 条 POI。
- 本地上传图片限制为 900KB/张，以避免超出浏览器存储配额。
- OTA 结果快照已接入；若要实时发起新一轮抓取，或接入真实 AI 模型和抖音发布，相关密钥必须保存在服务端，不能写入前端。

## 生产接入前置条件

1. 抖音开放平台/来客的应用主体、App ID、回调域名及图文发布权限。
2. OTA 数据的合法来源、授权范围、更新频率和图片使用边界。
3. AI 模型供应商、成本上限、数据出境与隐私策略。
4. 服务端、数据库、对象存储、任务队列和监控告警环境。
5. 种子商家账号与发布验收口径。

详细模型规则见 `AI_RULES.md`，工程质量分见 `CONTENT_QUALITY_SCORING.md`，运行时技能见 `skills/`，模块边界见 `ARCHITECTURE.md`，Agent 接手约束见 `AGENTS.md`。
